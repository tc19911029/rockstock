## 走查問題清單

> 類型：🧭 導航/IA　🔀 流程/一致性　🏷 標籤/文案　🧠 邏輯/正確性　🐢 摩擦/效率　💔 壞掉
> 嚴重度：🔴 阻斷　🟡 明顯影響　🔵 小　⚪ 待確認/主觀

| # | 頁面/流程 | 類型 | 嚴重 | 問題（使用者會怎麼撞到） | 建議 |
|---|---|---|---|---|---|
| **UX1** | 全域導航 / IA | 🧭 | 🔴 | **多個完整頁面在 UI 裡完全找不到入口、只能手打網址。** 桌面 nav 只有 持倉(/portfolio)+系統健康(/health)+主題；行動 hamburger 多 settings/disclaimer。實測+grep：`/etf`(0 連結)、`/risk`(0)、`/realtime`(0) 任何 nav/頁內連結都到不了；`/sizer`/`/journal`/`/growth`/`/today` **只從 `/risk` 連出**（而 /risk 自己只能手打）→ 整串被鎖。`/settings` 桌面 nav 缺（只行動有）。`PageShell.tsx:71` 註解自承「其餘舊頁可手打 URL」。對「有在用 ETF 追蹤/風險面板/部位試算/日誌/成長路徑」的你=每天都撞到。 | 桌面 nav 至少補一個「更多」選單或把這些頁收進去；或在首頁/持倉頁加入口。/etf、/risk、/realtime 優先 |

| **UX2** | `/agents/portfolio` 持股追蹤 | 🧠🏷 | 🟡 | 4 檔持股**現價全 = 進場價、損益全 0.00%**（南亞科現價顯 203.83、實際 ~360；損益 0.00% 實際 +75.69%）。頁面沒抓即時價、用進場價墊著，要按「準備檢視」才更新 → 使用者會以為「沒賺/沒動」，與 `/portfolio` 的 +75% 矛盾、被誤導。 | 未檢視前現價/損益顯「—」或「待檢視」，別捏造 0.00%；或比照 /portfolio 直接拉即時價 |
| **UX3** | Agent 系列流程（portfolio/backtest/memory/個股） | 🔀 | ⚪ | 「準備資料 → 離開頁面去 Claude Code 對話跑 skill → 回頁按重整」是跨 app 的重流程，對不熟的人不直覺。屬刻意的檔案橋接架構（CLAUDE.md 記載、省 API 成本），非 bug，但 onboarding 摩擦高。 | 流程框已有說明（好）；可考慮在按鈕旁加「為什麼要去對話跑」一句話 tooltip |

| **UX5** | `/portfolio` 持股「刪除」 | 💔🔀 | 🟡→🔴 | 持股「刪除」鈕 `remove(h.id)`（store line 293）**無任何確認、無 undo**，立刻把持股從 server `holdings.json` 永久移除（hard-delete、不留交易紀錄）。**對比**：profile 刪除有 `window.confirm`、批量分析有 confirm → 唯獨「永久刪真實持股」這個最危險的反而沒確認。手滑一下就掉一筆。 | 加 `confirm()`（比照 profile 刪除的「無法復原」警語）；或改成 archive/可復原 |
| **UX4** | `/portfolio` 今日操作建議 文案 | 🧠🏷 | ⚪ | 晶豪科觸發停損的建議寫「**開盤**以市價單全數賣出」，但書本規則（朱老師 13:20 看 / 13:25 掛市價；記憶明載「不可建議 09:00 開盤動作」）。其他股建議沒指定開盤 → 此處「開盤賣出」與書本時點矛盾。 | 改「13:25 掛市價」或拿掉「開盤」字眼，與書本一致；待確認是否刻意 |
| **UX6** | `/portfolio` 編輯/新增表單位置 | 🐢 | 🔵 | 點某張卡的「編輯」，表單 inline 開在**清單最上方**（不在你點的卡片旁），要往上找；長清單時更明顯。 | 表單就近展開、或用 modal、或自動捲到表單 |

| **UX7** | 亮色主題 | 🏷 | 🔵 | 切亮色後，操作建議綠/紅 banner 變很淡、低對比難讀；部分灰字/橘價在白底對比不足。暗色優先、亮色未調好（不破、但粗糙）。 | 補亮色配色 token，或若不維護亮色就把切換藏起來 |
