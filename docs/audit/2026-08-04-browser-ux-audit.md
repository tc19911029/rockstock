# Rockstock Chrome 使用者體驗稽核

日期：2026-08-04
方式：以 Chrome 實際開啟、瀏覽與操作現有頁面；桌面視窗約 1007×907，另檢查 375×812 響應式狀態。
範圍：首頁、持倉、健康、設定、掃描與回測、風控、即時盤、YouTube、ETF、Agents 等 26 個靜態功能頁。

## 結論

Rockstock 的能力已經很多，但目前更像「熟悉內部規則的人使用的操作台」，而不是第一次打開就能理解的產品。最大的問題不是配色或美觀，而是：

1. 正式站不可用，核心互動在本機檢查環境也未成功啟動。
2. 產品資訊架構沒有把大量功能交代給使用者。
3. 首頁同時塞入圖表、分析、持倉與數十種策略，缺少清楚的第一步與視覺層級。
4. 文案大量依賴內部術語、字母與維運指令，使用者很難知道「現在該做什麼」。
5. 操作元件普遍過小，且分頁的選取狀態與可存取性狀態不一致。

建議先處理 P0/P1 的可用性與資訊架構，再做視覺精修。若只調色、字體或卡片樣式，無法解決目前的主要使用障礙。

## 測試限制與環境事實

- 正式站 `https://stock-replay-5f24.vercel.app` 顯示 `Deployment Paused`，任何一般使用者目前都無法使用。
- 本機使用現有 `npm run dev -- -p 3001` 啟動後，可載入 SSR 畫面，但點擊「載入」、分析分頁、右側資料來源分頁與「新增第一筆持倉」都只取得焦點，沒有執行預期動作。
- 股票欄輸入 `2330` 後按「載入」會清空欄位，但畫面仍停在「尚未載入股票」；按 Enter 也沒有結果或錯誤提示。
- Chrome console 只記錄到泛化的 `Object` error，這一輪無法由瀏覽器輸出確認根因。因此「互動未啟動」是已確認現象，但「hydration 失敗」仍屬高可能性假設，不應直接當成根因結論。
- 多個資料頁長時間停留在「載入中…」或「無資料」。這可能部分來自本機資料/API 環境，不能一概判定正式資料功能壞掉；但缺少失敗與空狀態說明本身仍是 UX 問題。

## 優先級問題

### P0 — 阻斷使用

#### 1. 正式站部署暫停

- 重現：開啟正式站首頁。
- 實際：只顯示「This deployment is temporarily paused」。
- 影響：所有功能 100% 不可達。
- 建議：先恢復部署並增加外部可用性監控；首頁不可達應高於任何 UI 優化。

#### 2. 核心互動沒有結果，也沒有錯誤回饋

- 重現：本機首頁輸入 `2330` →「載入」；或在持倉空狀態點「新增第一筆持倉」。
- 實際：沒有載入股票、沒有開啟表單、沒有 toast、沒有欄位錯誤；使用者只會以為自己沒按到。
- 影響：首頁分析與持倉主流程不可完成。
- 建議：先確認 client hydration、事件綁定與錯誤邊界；所有非同步操作需有 loading、成功與就近錯誤訊息。股票不存在、格式錯誤、API 失敗要分開說明。

### P1 — 高影響使用問題

#### 3. 大量功能無入口，資訊架構近乎隱藏

首頁主要導覽只清楚露出「持倉」與「系統健康」，但實際另有：

- 自選股、設定、今日、即時盤、風控、成長路徑、交易日誌、鎖股、海外、倉位試算。
- ETF、法人、基本面補漲、回測排行榜、v12 績效／深度分析。
- YouTube 主頁、重播、老師、趨勢。
- Agents 候選池、決策、持倉檢視、回測、記憶。

使用者無法從產品本身建立功能地圖，只能知道網址或從程式碼發現。

建議：建立一層全域主導覽，依任務分組，而不是依技術模組分組：

- 今日決策：今日、掃描、鎖股、即時盤。
- 我的資產：持倉、自選股、風控、倉位試算、成長路徑、交易日誌。
- 研究情報：題材、法人、ETF、海外、YouTube。
- 驗證與回顧：策略績效、回測、Agents。
- 系統：資料健康、設定、免責聲明。

進階／維運功能可以放在「更多」或管理區，但不應完全沒有入口。

#### 4. 首頁沒有清楚的主要任務

初次進入同時看到：搜尋列、空 K 線圖、四個分析分頁、持倉、自選股、五種資料來源、台／陸、多／空，以及數十個策略按鈕。使用者不知道應該先：

- 搜尋一檔股票；
- 看今日推薦；
- 跑策略掃描；
- 還是先建立持倉。

建議把首頁改為「今日工作台」：第一屏只保留 3 個主要動作（查看今日機會、搜尋個股、檢視持倉）。策略掃描改為可展開的二層介面，詳細策略說明放在選取後的說明區。

#### 5. 策略層級與名稱對新使用者不友善

目前同時出現「Step 1 選股池、Step 2 多頭進場、反轉訊號、朱老師戰法、六條件(30分)、回後買上漲、K 線橫盤、三色(紅+雙B金叉/突破)」等大量名稱。

問題包括：

- 中英混用：Step 1／Step 2、daily action、fixedFraction、Kelly Half、Sharpe-like。
- 內部代碼直接暴露：B/C/E/K/L/M/P、Q、R、G/H/I、v11/v12。
- 名稱粒度不一致：有流程、有策略、有篩選器、有版本、有技術名詞。
- 同一畫面上說明句過長，窄欄下幾乎無法掃讀。

建議：顯示名稱用使用者語言，代碼作為次要標籤。例如「盤整突破（C）」；先說明「適合什麼市場／要找什麼股票／主要風險」，詳細規則再展開。

#### 6. 操作目標普遍過小

桌面首頁量到的常見高度：

- 「載入」24px。
- 分頁約 32–34px。
- 大部分策略按鈕只有 19px。
- 台股／陸股／多／空約 23px。
- 多個其他頁面的篩選器只有 19–36px。

手機 375px 模式下仍大量維持 19–34px。這低於常用的 44×44px 觸控目標建議，也讓密集介面更容易誤按。

建議：主要動作至少 40–44px；小型 filter chip 可以視覺上較小，但應以 padding 擴大實際點擊區。不要只為塞入更多策略而犧牲可操作性。

#### 7. 分頁可存取性狀態不一致

實際點擊「訊號／籌碼／基本面」或「YouTube 提及／題材分類／法人報告／ETF 追蹤」後，新分頁取得 `[active]` 焦點，但 `[selected]` 仍停留在「條件」或「策略掃描」，內容也沒有改變。

這同時是功能與 ARIA 問題：鍵盤與讀屏使用者無法知道真正選中的內容。

建議：採單一受控 tab state；點擊、Enter、Space、方向鍵都更新 `aria-selected`、tabpanel 與焦點。加入互動測試，驗證任一時刻只允許一個 tab selected。

#### 8. 空狀態與載入狀態沒有足夠行動指引

常見畫面是「載入中…」「無資料」「尚未產生」「跑 cron 後再查看」。這些文案沒有回答：

- 是資料真的不存在、正在讀取、讀取失敗，還是需要維護者先執行工作？
- 一般使用者可以做什麼？
- 何時會自動恢復？

例如基本面補漲頁直接顯示「跑 `?market=TW&force=1 cron` 後再查看」，回測頁要求執行 script。這是維運說明，不是一般產品操作。

建議定義四種明確狀態：Loading、Empty、Error、Admin action required。一般使用者只看到可理解的下一步；維運指令放在可展開的「技術細節」或管理頁。

### P2 — 呈現、文案與一致性

#### 9. 視覺密度超過有效掃讀上限

1007px 寬時首頁被切成圖表、分析／持倉與右側策略三欄。右欄約 240px，卻塞入五個資料分頁、多組長說明與二十多個策略按鈕，文字縮小且對比低。

建議：在 1024px 以下改為兩欄或抽屜；策略面板至少 320–360px。把說明移到被選中項目的 detail panel，清單只留名稱、狀態與數量。

#### 10. 重複、矛盾或不自然的文案

- 每頁可存取樹同時出現「跳至主要內容」與「跳到主要內容」兩個 skip link。
- 持倉空狀態連續出現兩段幾乎相同的免責說明。
- 「持倉 daily action 載入中…」中英混用且不面向一般使用者。
- 健康頁「看到紅燈/黃燈怎麼辦？」後直接提供 `npx tsx ...`，受眾從使用者突然切成開發／維運者。
- 「這不是明牌（已被回測打臉）」「老實話」雖有個性，但與其他頁的正式語氣差距大，重要風險資訊應一致、克制且可比較。

建議先建立術語表與文案規則：繁中為主、英文縮寫首次出現需解釋；同一概念只能有一個名稱；風險說明採固定結構。

#### 11. 標題與頁面識別不足

大量頁面沒有語義上的 H1，瀏覽器 title 全部都是「K線走圖練習器 — 台股陸股掃描選股與策略回測」。進入 Agents、風控、設定或 YouTube 頁後，瀏覽器分頁與讀屏都無法辨識目前位置。

建議：每頁唯一 H1；每個 route 設定專屬 metadata title，例如「持倉｜Rockstock」「策略回測｜Rockstock」。頁首同時提供目前位置與返回上層，而不是只顯示 ⬅️ emoji。

#### 12. Emoji 與圖示系統不一致

介面同時用 emoji（💼、📺、🔥、🏦、📈、⬅️）、星號字元與 SVG 圖示。emoji 在不同作業系統外觀不同，也讓專業金融工具顯得不一致。

建議：導覽與操作統一採同一套 SVG icon；emoji 可保留在內容標籤或少量強調，不應作為主要功能圖示。

#### 13. 設定頁混合帳號設定、策略原則、通知、導覽與危險操作

設定頁同時包含 Email、通知門檻、固定策略說明、停損 slider、掃描時間、漲跌色、功能捷徑、導覽重播、免責與清除全部資料。缺少類別層級，「清除所有數據」也與一般設定距離太近。

建議拆成：偏好、通知、交易風控、資料與隱私。危險操作獨立區塊，二次確認需明確列出會刪除的項目；Email 測試發送屬外部副作用，應顯示發送目的地與結果。

#### 14. 手機版可用但觸控密度仍過高

375px 時首頁會把中間分析面板折疊、持倉與資料來源改為單欄，沒有大範圍水平溢出；但仍有約 7px 文件寬度溢出，且策略 chip 保持 19px 高，五個資料來源分頁各約 53–56px 寬，文字被縮成「掃描／節目／題材／法人／ETF」。

建議手機版不要直接壓縮桌面全功能：首頁只顯示主要任務；策略清單改全寬 list / bottom sheet；次要文字不應靠縮小字體解決。

## 建議的優化順序

### 第一階段：恢復可用（P0）

1. 恢復正式部署。
2. 修復本機／正式環境的 client 互動與錯誤邊界。
3. 為搜尋載入、分頁切換、新增持倉建立最小 E2E 測試。
4. 將 Loading／Empty／Error／Admin-required 狀態分開。

### 第二階段：重整資訊架構（P1）

1. 建立全域主導覽與任務分組。
2. 把首頁改為「今日機會、搜尋個股、我的持倉」三個主要入口。
3. 策略採兩層選擇：類別 → 策略；代碼移到次要資訊。
4. 整併 YouTube、Agents、回測等各自的子導覽。

### 第三階段：改善操作與可存取性（P1/P2）

1. 放大觸控目標與主要字級。
2. 修正 tabs 的 selected／focus／tabpanel 關係與鍵盤操作。
3. 每頁補唯一 H1、專屬 title、breadcrumb 或明確返回名稱。
4. 移除重複 skip link，統一圖示系統。

### 第四階段：文案與視覺精修（P2）

1. 建立繁中術語表，統一版本、字母與策略命名。
2. 把維運指令收進技術細節，不直接當一般空狀態。
3. 統一風險揭露卡片的語氣與結構。
4. 最後再處理字體、間距、色彩與圖表視覺一致性。

## 下一輪建議驗證任務

修復正式部署與互動後，應用真實資料完成以下端到端路徑：

1. 首次使用者：進站 → 理解產品 → 找到今日機會。
2. 個股研究：搜尋 2330 → K 線 → 條件／訊號／籌碼／基本面 → 加自選。
3. 持倉管理：新增持倉 → 查看損益與停損 → 匯出 → 匯入還原。
4. 策略研究：選市場 → 選策略 → 看候選股 → 看原因 → 回測證據。
5. 行動決策：從候選股 → 倉位試算 → 加入持倉／監控。
6. 手機：375px 下完成搜尋、看候選股、加自選與查看持倉。
7. 鍵盤：不使用滑鼠完成主導覽、tabs、搜尋與表單操作。

只有完成這些實際流程後，才能對資料正確性、操作效率與完整互動品質做第二輪結論。

## 第二輪深挖：以使用者任務檢查 UI／UX

本輪不再只問「元件有沒有顯示」，而是用六個問題逐頁檢查：

1. 我現在在哪裡？
2. 這頁主要要我做什麼？
3. 下一步在哪裡？
4. 按下去會發生什麼？
5. 系統現在是等待、成功、沒資料，還是失敗？
6. 我能不能恢復、返回或改變決定？

答案顯示，目前最大的 UI／UX 債務是「功能很多，但產品沒有替使用者整理決策順序」。

### 新增 P0/P1 證據

#### 15. 768–1280px 寬度會實質裁掉右側研究面板（P0/P1）

首頁三欄使用近似固定寬度：K 線約 500px、分析／持倉 256px、右側資料面板 600px。

實測：

- 768px viewport：分析面板位於 x=500–756；右側資料面板從 x=764 開始、寬 600px，幾乎整塊在視窗外。
- 1007px viewport：右側 600px 面板只剩約 243px 可見，長策略名稱與說明被壓縮。
- 1440px viewport：三欄才完整顯示。
- 文件寬度在 768px 仍回報 768px，沒有可用的水平捲動來取回被裁內容。

使用者影響：一般平板、半螢幕視窗與部分筆電寬度下，「策略掃描、YouTube、題材、法人、ETF」不是變窄，而是直接消失或只露出殘片。

建議斷點：

- ≥1366px：可保留三欄，但右側至少 360px，避免用 600px 固定欄寬。
- 900–1365px：改兩欄，右側研究面板變抽屜或下方全寬區塊。
- <900px：任務式單欄；K 線、分析、持倉、情報一次只顯示一個主區塊。

#### 16. 首頁的鍵盤路徑與閱讀負擔過長（P1）

首頁空狀態已有約 55 個可聚焦控制項：

- 使用者要經過約 30 次 Tab，才會到第一個策略「六條件」。
- 兩個重複 skip link 佔用前兩個焦點。
- 同一頁要依序穿過搜尋、全域導覽、圖表控制、四個分析 tabs、持倉、自選、五個資料來源 tabs、兩組市場篩選，才進策略清單。

這代表 DOM 與視覺結構都沒有提供「略過整組策略」「直接到研究面板」等捷徑。

建議：

- tabs 只讓選中的 tab 進 Tab 順序，其餘用左右方向鍵切換。
- 策略清單採 roving tabindex 或 combobox／command palette，而非幾十個平行按鈕。
- 補「跳到個股分析」「跳到持倉」「跳到策略結果」三個區域捷徑。
- 移除重複 skip link。

#### 17. 首頁文字不是緊湊，而是低於一般可讀尺度（P1）

在 1440px 完整桌面畫面量測 79 個主要文字／控制樣本：

- 9px：9 個。
- 10px：28 個。
- 11px：9 個。
- 12px：26 個。
- 14px 以上：僅 7 個。

也就是約 84% 的樣本低於 14px。Step 標題與說明為 9px，大多數策略按鈕為 10px；這些不是補充資訊，而是核心操作。

建議桌面最小正文 13–14px、重要標籤 14px、主要按鈕 14–16px；不要靠縮字塞入完整策略目錄。應以分組、搜尋與漸進揭露降低同屏資訊量。

### 首頁：使用者心理模型

#### 18. 產品沒有自我介紹，也沒有頁面主標題

頁首直接從股票搜尋框開始，沒有 Rockstock 名稱、目前頁面名稱或「今天要做什麼」的提示。右上只有三個 icon，視覺上無文字標籤。

第一次進站的使用者無法立即回答：

- 這是選股器、K 線練習器、持倉工具，還是 AI 決策平台？
- 系統資料是哪一天？
- 今天掃描完成了嗎？
- 我應先載入個股，還是從掃描結果選一檔？

建議頁首顯示「Rockstock 今日工作台」、交易日／資料日與更新狀態。首頁第一區先給 1–3 個今日行動，而不是直接給完整工具牆。

#### 19. 空狀態浪費主要畫布，沒有完成 onboarding

未選股票時，K 線區佔約 500×858px，中央只顯示「載入K線圖中…」；分析區顯示「尚未載入股票」，但沒有範例、最近查看、熱門標的或從今日候選股選取的捷徑。

「尚未選股票」與「載入K線圖中」也互相矛盾：前者代表尚未開始，後者代表系統正在處理。使用者會不知道要等待還是操作。

建議未選股時顯示 onboarding 空狀態：

- 搜尋或選擇一檔股票。
- 最近查看。
- 今日候選前三檔。
- 一個 30 秒的「如何看這頁」。

只有真正發出資料請求後才顯示 loading；失敗則顯示原因與重試。

#### 20. 「加自選」停用但沒有解釋

空狀態下「☆ 加自選」是 disabled。它很可能是因為尚未載入股票，但 UI 沒有 tooltip 或就近提示。使用者只看到一個不能按的主要動作。

建議空狀態直接隱藏，或保留時顯示「先選擇股票即可加入自選」。disabled 元件本身通常不能取得焦點，說明不能只放在 hover tooltip。

#### 21. 持倉區的層級難以理解

同一區連續出現：

- 「持倉 0」折疊列。
- 「持倉／自選股」兩個按鈕。
- 「我的」按鈕。
- 「全部／台股／陸股」篩選。
- 「新增持倉」。

「我的」看起來像帳號或個人選單，但實際可能是持倉檔案；「持倉」同時是導覽名稱、折疊標題與 tab。使用者不容易形成層級。

建議改為：區塊標題「我的股票」→ tabs「持倉／自選」→ market filter。持倉檔案若真的支援多人／多組合，應明確命名「投資組合：我的」而非單獨一個「我的」。

#### 22. 策略篩選沒有結果上下文

右側先顯示市場、方向、Step 1／Step 2 與數十個策略，但空狀態沒有：

- 掃描日期與更新時間。
- 每個策略的命中數量。
- 目前選取條件摘要。
- 結果為空、尚未掃描或資料載入中的區別。
- 清除所有篩選或回到推薦設定。

建議在策略列表上方固定顯示「資料日、最後更新、目前條件、結果數」。策略按鈕應顯示 count，並把「推薦／常用」放前面，其餘收進更多策略。

### 持倉：從空狀態開始的任務

#### 23. 空持倉時仍啟用匯出與 CSV（P1/P2）

持倉數量為 0 時，「匯出」與「CSV」仍為 enabled。使用者點擊後不是得到空檔，就是沒有結果；兩者也沒有說明差異。

建議：

- 無資料時停用並顯示原因，或直接隱藏。
- 合併成「匯出」選單，選項為「完整備份 JSON」「持倉表 CSV」。
- 「匯入」改成標準 button，提供支援格式與是否覆蓋現有資料的說明。

#### 24. 持倉空狀態有 CTA，但文案與層級仍不完整

優點：有「新增第一筆持倉」和「去掃描選股」兩條合理路徑。

問題：

- 沒有 H1，頁面只靠 header 裡的「💼 持倉」辨識。
- 空狀態主標只有 14px、說明 12px、免責文字 10px。
- 「持倉 daily action 載入中…」直接暴露內部流程名稱。
- 兩段免責聲明重複，且中間相隔約 79px，看起來像散落的註腳。
- 「我的」仍無法說明是帳號、投資組合還是持倉檔。

建議空狀態主標 20–24px，說明至少 14px；把兩段免責整併成一次。將技術載入名稱改為「正在更新今日持倉建議」。

### 設定：控制範圍與危險操作

#### 25. Email 欄位靠 placeholder 當名稱（P1 可存取性）

Email input 沒有可確認的 `<label for>` 或 aria-label，只顯示 placeholder「輸入你的 Email」。輸入後提示會消失，使用者無法回看欄位用途；讀屏名稱也不穩定。

建議固定 label「通知收件信箱」，placeholder 只提供格式示例，例如 `name@example.com`。欄位下方說明資料用途、是否儲存在本機／伺服器以及如何停用通知。

#### 26. 「儲存」的作用範圍不明

設定頁包含 Email、門檻、停損、色彩等多組控制，但只有一個寬 424px 的「儲存」位於 Email 區。使用者難以判斷：

- 它只存 Email 與通知門檻？
- slider 與色彩是即時儲存？
- 離開頁面前需不需要再按一次？

建議每區採一致策略：全部即時儲存並顯示「已儲存」，或頁尾提供單一 sticky「儲存所有變更」。不要混合兩種模型而不說明。

#### 27. 設定頁暴露內部文件，且可編輯／不可編輯內容混在一起

「所有條件…依寶典 2024，不開放 UI 調整（CLAUDE.md Rule 5）」把內部檔名與開發規則顯示給產品使用者。旁邊的「自動掃描時間」看起來屬於設定，但實際只讀。

建議改成使用者語言：

- 「選股條件採固定版《寶典 2024》，此處不提供自訂。」
- 「系統排程（唯讀）」並說明時區與下一次執行時間。

#### 28. 停損 slider 的語義與可操作性不足

- track 高度只有約 6px。
- 「停損比例 ⓘ」按鈕高度約 16px。
- slider 在可存取樹只呈現數值 `7`，沒有清楚名稱。
- 畫面顯示 `-7%`，slider value 則是 `7`，正負號模型不一致。

建議用「最大可承受跌幅 7%」避免正負混淆，提供數字輸入＋slider；補 min/max/step、即時風險說明與固定 label。

#### 29. 通知測試具有外部副作用，但缺少目標確認

「測試發送」會對外寄信，卻沒有在按鈕旁顯示會寄到哪個地址、寄送中、成功、失敗或重試。Email 尚未填寫時按鈕仍呈 enabled。

建議只有 Email 格式有效且已儲存後才能測試；按鈕寫成「寄送測試信到 t***@example.com」，並提供明確狀態回饋。

### 部位試算：專業功能的認知門檻

#### 30. 欄位視覺標籤存在，但程式關聯不足

畫面有「股票代號、名稱、進場價、停損價」文字，但多個 input 沒有可確認的 label association／accessible name：

- 股票代號的讀屏名稱來自 placeholder `2330.TW`，不是「股票代號」。
- 名稱、進場價、停損價與總資產欄在可存取樹缺少清楚名稱。
- select 也沒有穩定 accessible name。

建議所有表單採明確 `label for`／id，錯誤訊息以 `aria-describedby` 關聯。

#### 31. 必填與選填互相矛盾

「總資產手動覆寫（選填）」的 placeholder 卻是「必填」。試算按鈕在進場價、停損價與總資產空白時仍 enabled。

使用者無法知道最低輸入需求，也不知道系統是否會使用預設資產。

建議在表單頂端先說明必填欄位；如果總資產有預設來源，顯示實際採用值與來源。只有足夠資料時才可試算，或點擊後在欄位下顯示就近錯誤。

#### 32. 技術模型與內部設定蓋過真正答案

頁面直接出現 `entry/stop`、`growth-path`、`fixedFraction`、`Kelly Half`、`letter-aware mode`、`sizing-config.json`、`perIndustryMaxPct`。但使用者真正想知道的是：

- 建議買幾張？
- 最多可能虧多少？
- 這筆交易佔總資產多少？
- 為什麼是這個數字？

建議結果先以四個白話 KPI 呈現，再提供「計算方式」展開區。內部檔名與 config key 不應出現在一般介面。

#### 33. 「買法字母」需要翻譯層

select 只列 B、C、D…Q，沒有顯示策略名稱；預設文案「不指定（走 fixedFraction）」也不是一般使用者語言。

建議選項改為「B｜回後買上漲」等可辨識名稱；預設改為「使用一般風險比例」。代碼保留給熟悉方法的使用者，但不能成為唯一識別。

### 健康、回測與 Agents：使用者和維運者混在一起

#### 34. 健康頁在仍載入時就先顯示紅色故障（P1）

同一畫面同時出現：

- 右上「載入中…」。
- 中央「載入健康資料中…」。
- 紅色「需要處理」。
- 台股／陸股「無資料」。

在請求尚未完成時把初始空值當成故障，會造成假警報。使用者也看不到最後更新時間或「重試」。

建議 loading 階段只顯示 skeleton；取得結果後才判定綠／黃／紅。故障卡需附「檢查時間、受影響功能、一般使用者影響、重試／回報」四項。

#### 35. 回測頁把研究指標、篩選與系統維運混在同一閱讀層

「反指標、Paper-trade、d1/d3/d5、1天／20天／100天樣本、排序 alpha、harness」連續呈現。`d1` 和「1天」分別代表觀察期與樣本門檻，但外觀都是小按鈕，容易混淆。

建議先給一句結論：「哪些策略目前有足夠證據／哪些不應使用」。把控制分為「報酬期間」「最小樣本」「市場」「策略類型」並加 group label。產生資料的 script 放管理頁，不放一般空狀態。

#### 36. Agents 流程不是單一產品流程

多個頁面要求使用者：

1. 在 Rockstock 按「準備」。
2. 到對話視窗執行特定指令。
3. 等外部代理產生檔案。
4. 回 Rockstock 按「重整」。

目前沒有跨步驟的進度、任務 ID、預計時間、失敗原因或「前往對話」深連結。按鈕名稱「準備檢視／準備反思」也沒有說明只會寫暫存資料，不會直接產生結果。

建議把它設計成 stepper：準備資料 → 啟動分析 → 分析中 → 可查看；每步顯示產物、時間與下一動作。若仍需外部對話，應提供明確 handoff CTA 與回來後可辨識的任務狀態。

### 一致性與信任

#### 37. 頁面命名、返回與導覽模式不一致

- 大多頁面沒有 H1。
- 瀏覽器 title 全站相同。
- 有些頁返回 `/`，有些返回 `/agents`、`/health?tab=market` 或 `/v12-performance`。
- 返回控制視覺上多半只有 ⬅️ emoji，沒有上層名稱。
- 全域導覽只顯示持倉、健康、主題，卻在設定頁放自選／持倉／掃描捷徑。

建議建立一致 app shell：產品名、主導覽、目前頁面、breadcrumb、資料日期、全域狀態。返回應寫「返回 Agents」或「返回資料健康」，讓使用者可預測目的地。

#### 38. 語氣在專業、課程筆記與開發工具間跳動

同站同時使用：

- 專業風險語氣：「僅供學習參考，非投資建議」。
- 課程語氣：「朱老師戰法」「寶典 2024」。
- 口語語氣：「已被回測打臉」「老實話」。
- 開發語氣：「CLAUDE.md Rule 5」「cron」「script」「config key」。

這會削弱金融決策工具最重要的信任感。建議明確定義品牌聲音：直接、誠實、證據導向，但避免內部黑話。每個研究結論統一用「結論／證據／限制／如何使用」格式。

## 重新定義首頁的建議任務模型

若以一般使用者而非開發模組設計，首頁可改成以下順序：

1. **今天發生什麼**：資料日期、健康狀態、今日候選與重要警示。
2. **我現在該做什麼**：檢查持倉、查看 3 個候選、沒有行動。
3. **研究一檔股票**：搜尋 → 個股工作區。
4. **我的股票**：持倉／自選的今日變化與風險。
5. **更多研究**：策略、題材、法人、ETF、YouTube，作為次級入口。

K 線與完整策略目錄不一定要消失，但應在使用者選定股票或選擇「進階研究」後才展開。這能同時保留專業深度，又不讓首次使用者被工具牆淹沒。

## 第二輪建議優先處理清單

1. 修復 768–1280px 右側面板被裁切。
2. 把首頁核心字級從 9–12px 提升到可讀範圍，策略改分組／搜尋。
3. 建立一致 app shell、H1、頁面 title 與全域導覽。
4. 分離未開始、載入中、空資料、錯誤與維運需求。
5. 重做首頁未選股空狀態與今日工作台。
6. 修正設定與試算表單的 label、必填規則與儲存模型。
7. 把內部檔名、cron、script、config key 移出一般使用介面。
8. 重整持倉資料管理與空狀態。
9. 把 Agents 外部 handoff 做成可追蹤的 stepper。
10. 統一品牌語氣、策略命名與風險證據格式。

## 第三輪深挖：決策可信度與跨頁旅程

本輪從一條完整投資工作流出發：

> 發現候選 → 理解原因 → 判斷證據 → 計算部位 → 加入持倉 → 追蹤風險 → 事後回顧

結果顯示 Rockstock 已經有這些能力的零件，但各零件目前沒有形成連續、可驗證的使用者旅程。

### 導覽可達性

#### 39. 首頁只能到達 2 個功能頁（P1）

以 Chrome 實際讀取可見內部連結：首頁只有：

- `/portfolio`：持倉。
- `/health`：系統健康。

首頁沒有可見連結前往自選股、設定、今日、風控、部位試算、交易日誌、鎖股、Agents、回測、YouTube、ETF 或海外情報。右側的題材／法人／ETF 是頁內 tab，不是完整功能地圖。

這表示使用者即使知道「系統可能有這個功能」，也無法靠探索找到它。

建議把全域導覽視為必要產品骨架，而非捷徑集合。至少需固定露出：今日、研究、我的股票、回顧、更多／設定。

#### 40. 29 個頁面中有 5 個導覽孤島（P1）

以下 route 在實際畫面中沒有任何可見內部連結：

- `/etf`
- `/today`
- `/youtube`
- `/youtube/replay`
- `/youtube/trends`

若 client redirect 或資料載入失敗，使用者會落在空白頁，而且無法返回。其他大部分頁面也只有「⬅️、持倉、健康」三個連結。

建議所有 route 都必須由一致 app shell 包覆，即使頁面載入失敗也要保留主導覽、頁名、返回與錯誤恢復。空白 route 若已廢棄，應移除；若是 redirect，應由 server 完成而非依賴 client hydration。

#### 41. 「返回」取代了真正的資訊架構

大量頁面只有一個 ⬅️，使用者只能回到來源，不能橫向前往下一個任務。例如候選池看完後沒有「進入代理分析／試算部位」，回測看完也沒有「查看策略候選」。

建議在每個結果頁提供與任務相關的下一步，而不是只提供歷史返回：

- 候選股 → 查看個股理由。
- 個股理由 → 部位試算／加自選。
- 部位試算 → 新增持倉。
- 持倉 → 查看風險／寫交易日誌。
- 已結束交易 → 回顧與策略績效。

### 資料時效與信任

#### 42. 決策頁普遍缺少實際資料日期（P0/P1）

檢查 12 個決策、風控與績效頁的使用者可見內容：Agents、候選池、風控、成長路徑、日誌、鎖股、Smart Money、海外、回測、YouTube 老師、v12 績效、健康。

除了說明中的「近 7 天／近 20 天／每日 19:05」等相對字樣外，畫面幾乎沒有呈現實際資料日或最後更新 timestamp；10 個頁面同時處於 loading 或 empty 狀態。

對金融決策產品而言，沒有日期就無法判斷：

- 這是今天的建議還是歷史結果？
- 今日盤後流程是否已完成？
- 數據落後一日是否仍可使用？
- 目前顯示 0 是真實 0，還是尚未載入？

建議所有決策卡使用固定 metadata 列：

- 資料截至：2026-08-04 收盤。
- 計算完成：2026-08-04 19:12 CST。
- 資料完整度：98.7%。
- 狀態：可使用／部分缺失／過期／計算中。

過期資料需在整頁持續可見，而不是只用一次 toast。

#### 43. 「0」同時可能代表沒有結果、尚未載入或分析未開始

Agents 顯示「全部 0／進場 0／完成 0」，候選池顯示「— 載入中…」，個股代理頁又顯示「未開始 · 0/4」及「載入中…」。使用者無法知道零值的語義。

建議載入前不要渲染業務數字 0，改用 skeleton。只有資料請求成功且結果確實為空時才顯示「0 筆」，並交代資料日與篩選條件。

#### 44. 有歷史代理檔案，UI 仍呈現「未開始」

專案資料中存在 `2026-05-25/2317.TW` 的 decision、technical、chip、fundamental、news、risk、bull、bear 等完整檔案；但開啟 `/agents/2317.TW?date=2026-05-25`，頁面仍顯示：

- 「未開始 · 0/4」。
- 「載入中…」。
- 「開始準備」「重整」皆 disabled。

這一現象可能是目前本機 client/API 未啟動造成，不能直接推論正式資料索引錯誤；但對使用者而言，它暴露出一個必要 UX 原則：不能只顯示流程狀態，還要說明資料載入失敗、找不到 run、symbol 格式不符或日期不存在等具體原因與恢復方式。

#### 45. 資料來源與信心沒有統一呈現

不同頁各自出現「綜合評分、等級 A–E、面向燈號、YouTube 提及、題材熱度、勝率、Sharpe-like、回測 alpha」，但沒有共同的證據模型。

使用者無法比較：

- A 級和 80 分的關係。
- 分析師一致與資料完整度的差別。
- 回測勝率高但樣本少，是否優於勝率較低但樣本多。
- YouTube 共識究竟是訊號、佐證，還是只供參考。

建議所有建議結果採統一格式：

1. **結論**：觀察／可研究／不建議。
2. **信心**：低／中／高，並說明由資料完整度與代理一致度組成。
3. **三個主要理由**。
4. **最大反對理由**。
5. **失效條件**。
6. **證據日期、樣本量與來源**。

### 決策與回顧混淆

#### 46. Agents 把事前判斷與事後報酬放在同一排序層

Agents 頁的排序選項同時包括：

- 決策優先、等級、綜合評分。
- 漲跌·開盤缺口、1日、5日、10日、20日、最高、最低。

前三者是當下決策訊號，後者是事後結果。若沒有明確切換「當日決策／事後驗證」，使用者可能用未來報酬排序歷史決策，造成 hindsight bias，甚至誤以為系統當時已知道結果。

建議拆成兩個 mode：

- **當日決策**：只能使用當時已知資料排序。
- **事後回顧**：清楚標記 hindsight，專門評估決策品質。

日期、資料截點與進場假設必須固定顯示。

#### 47. 候選池把來源、人氣與績效混成同一排名

候選池可用「加權總分、YouTube 提及、今日題材熱度、漲跌·1/5/10/20日、最高／最低」排序，也可手動調權重。這把不同目的的指標放在同一平面：

- 候選資格。
- 當下人氣。
- 歷史／未來績效。
- 使用者偏好權重。

建議先問使用者的目的：「找今日新機會」「驗證模型」「追蹤熱門題材」。每個 mode 只顯示相關排序。權重設定屬進階研究，不應放在主決策流程的第一層。

#### 48. 回測頁的時間與樣本控制命名容易誤讀

同一列出現 `d1/d3/d5` 與 `1天/20天/100天/300天`。前者是報酬觀察 horizon，後者似乎是最小樣本／常出現條件，但兩組外觀相同，使用者會把它們都理解成持有期。

建議使用 group label 與白話名稱：

- 報酬觀察：1 日、3 日、5 日。
- 最小樣本：1、20、100、300 次。

「300天（常出現）」應改成「至少 300 次觸發」，避免把次數寫成天數。

#### 49. Paper-trade 進場文案自相矛盾

頁面寫「進場=隔日收盤≈13:25」。13:25 並不是收盤價，這會讓使用者不知道回測用的是收盤前快照、13:25 成交價，還是正式收盤價。

即使計算本身正確，文案也會削弱信任。建議明確寫出：

- 訊號產生時間。
- 模擬下單時間。
- 使用價格欄位。
- 是否含手續費與滑點。

### 跨頁規則與用詞矛盾

#### 50. 全域漲跌色設定與個別頁說明可能衝突

設定頁允許「紅漲綠跌」或「綠漲紅跌」，但 Smart Money 與回測頁文案固定寫「紅=漲、綠=跌」。如果使用者選擇歐美慣例，頁面文字與實際顏色至少有一方會錯。

建議所有頁面從同一 color-semantics 設定產生圖例，文案不要硬編碼顏色。除了顏色，數值前需有正負號／箭頭，避免只靠色彩傳達結果。

#### 51. 已證偽策略仍以功能頁形式存在，行動暗示矛盾

Smart Money 頁開頭說「這不是明牌（已被回測打臉）」「不要照著買」，後面仍說明篩選條件、隔天進場與停損。使用者會收到兩個互相競爭的訊息：不可用，但又像一套完整交易策略。

建議：

- 若策略已證偽，移至「研究封存／反例」而非主要功能。
- 清單改成教育用途，移除進場 CTA。
- 以「為何失效、何種市場下失效、未來需要什麼證據才重啟」取代操作指示。

#### 52. v11／v12 字母改名增加使用者記憶成本

績效頁顯示「G/H/I 為 v11 字母（J/K/L 為 v12 改名）」。使用者需要先理解版本歷史，才能看目前策略；其他頁又使用 B–Q 字母。

建議 UI 永遠以穩定策略名稱為主，字母只是 badge。版本映射放 tooltip 或文件，不要佔用主要分析畫面。歷史資料應由系統自動映射到同一策略 identity。

#### 53. YouTube 老師回測缺少初始可信度資訊

頁面說明平均漲幅與勝率，但初始說明沒有先交代：

- 每位老師／每格的樣本數。
- 重複提及如何計算。
- 隔日開盤是否可能買不到漲停股。
- 手續費、滑點與市場期間。
- 節目提及是推薦、討論還是負面看法。

建議每個績效格至少同時顯示平均報酬、勝率、樣本數與資料區間；樣本太少時不以深色強調。把語意分類（推薦／觀察／負面）納入模型或明確標示限制。

### 風險資訊的位置

#### 54. 風險常以長段警語出現，沒有轉化成可行動限制

Rockstock 很常誠實揭露限制，這是優點；但目前多為小字長段落，例如：

- 僅供學習、非投資建議。
- 樣本短、大多頭期間。
- 不含手續費／滑點／倉位限制。
- 不入選股分數。
- 緊迫度不代表勝率。

使用者容易略過，也不知道它會如何改變操作。

建議將風險結構化：

- **資料限制**：樣本 7 個月。
- **模型限制**：未計滑點。
- **使用限制**：只能觀察，不提供進場建議。
- **操作上限**：單筆風險不得超過 X%。

若限制重大，系統應直接限制 CTA 或降低信心，而不只是增加警語。

#### 55. 缺少「為什麼不是現在」的負面決策

多數工具都在找候選、打分或排名，但使用者更需要知道：

- 為什麼今天不該進場？
- 還差哪一個條件？
- 什麼價位／事件出現才重新評估？
- 哪個風險一旦發生就失效？

鎖股頁已有「在等什麼」的概念，應提升為全站一致模型。每個候選顯示「目前狀態、等待條件、失效條件、下次檢查時間」，比只給分數更能支持真正決策。

## 建議的決策頁卡片規格

每一檔股票在首頁、候選池、Agents、持倉與回顧頁都應沿用同一資訊順序：

1. 股票名稱／代號／市場。
2. 資料截至時間與是否過期。
3. 當前狀態：等待／可研究／已有持倉／風險升高／退出。
4. 一句白話結論。
5. 三個主要理由。
6. 最大反方理由與失效條件。
7. 信心、樣本量與資料完整度。
8. 下一個合理動作：看詳情、試算、加自選、更新停損、寫回顧。

同一股票跨頁不應重新發明名稱、顏色、分數或狀態。這會大幅降低使用者在多模組間切換的認知成本。

## 第三輪建議優先處理清單

1. 所有決策與績效頁固定顯示資料日、完成時間、完整度與過期狀態。
2. 建立真正可遍歷的全域導覽，消除 5 個零連結 route。
3. 分開「當日決策」與「事後回顧」，避免 hindsight 指標混用。
4. 統一股票決策卡與證據格式。
5. 統一色彩語義、策略 identity 與版本映射。
6. 把已證偽策略移到研究封存，不再暗示可操作。
7. 釐清 Paper-trade 的訊號、下單時間與使用價格。
8. 把長警語轉成資料限制、模型限制、操作限制與實際 UI 約束。
9. 讓候選股顯示等待條件、失效條件與下次檢查時間。
10. 把候選 → 個股 → 試算 → 持倉 → 回顧串成可連續完成的流程。

## 第四輪：手機版與無障礙深挖

測試條件：Chrome、375 × 812 viewport、local development build。以下尺寸與溢出量為瀏覽器實測，不是視覺猜測。

### 手機版量化摘要

| 頁面 | viewport 寬 | document 寬 | 水平溢出 | H1 |
|---|---:|---:|---:|---|
| 首頁 | 375px | 382px | 7px | 無 |
| 投資組合 | 375px | 429px | 54px | 無 |
| 設定 | 375px | 375px | 0px | 無；由 H2 開始 |
| 倉位計算器 | 375px | 510px | 135px | 無 |
| 系統健康度 | 375px | 375px | 0px | 有 |
| Agents | 375px | 471px | 96px | 無 |
| 回測排行榜 | 375px | 450px | 75px | 無 |

7 個關鍵頁中只有系統健康度有 H1。首頁在手機畫面仍呈現 53 個可見操作元件；幾乎每一個元件至少有一個邊長小於 44px。

### 已確認缺陷

#### 56. 四個核心頁在 375px 手機寬度產生明顯水平溢出

投資組合、倉位計算器、Agents、回測排行榜分別超出 viewport 54、135、96、75px。這不是 1–2px 的 rounding error，而是足以讓欄位、標題或操作消失在畫面外的版型失效。

其中倉位計算器最嚴重：頁面寬 510px，代表超過四分之一內容位於初始 viewport 之外。使用者若不知道可以橫向滑動，會直接漏掉欄位；若容器隱藏 overflow，則會完全無法操作。

建議將 375px 設為 CI visual test 的最低必測寬度，並加入斷言：`document.documentElement.scrollWidth <= window.innerWidth`。資料表可以例外使用明確標示的內部水平捲動區，但整頁不應橫向捲動。

#### 57. 手機 header 保留桌面排列，導覽與控制被推到畫面外

在投資組合、倉位計算器、Agents 與回測頁，header 右側控制的 x 座標超過 375px；實測最遠分別到約 429、511、472、451px。這表示 responsive 行為只是讓 viewport 變窄，並未重新安排導覽。

建議在手機改成：品牌／頁面名稱 + 一個主要動作 + overflow menu。主題、設定、次要導覽收入選單，不要維持桌面橫列。

#### 58. 觸控熱區普遍低於 44 × 44px

首頁可見 53 個操作元件，多數高度只有 19–34px：

- 搜尋框與載入按鈕：24px 高。
- 自選清單：26px 高。
- 市場篩選與部分策略按鈕：19px 高。
- 投資組合 tabs：30px 高。
- 來源 tabs：33–34px 高。
- 系統健康度的複製按鈕：約 19 × 13px。
- 回測的 d1／d3／d5 與樣本控制：24px 高。

這會造成誤觸、難以瞄準，也讓高齡、手部動作不穩或單手操作的使用者特別吃力。建議互動元件最小熱區 44 × 44px；視覺圖示可以較小，但外層 button 必須補足 padding。

#### 59. 倉位計算器在手機仍維持雙欄，且 7 個欄位缺少可程式辨識名稱

倉位計算器在 375px 下仍使用約 150px 寬的雙欄表單，直接造成 135px 溢出。檢查到的 7 個欄位沒有對應 `label` 或 `aria-label`，部分只能依賴 placeholder 猜用途。

這同時是 UX 與無障礙問題：placeholder 輸入後消失，錯誤時使用者無法回想欄位定義；螢幕閱讀器也無法可靠宣告欄位名稱。

建議手機改成單欄，所有欄位使用常駐 label；金額、價格、百分比需顯示單位與可接受範圍，並提供合適的 `type`／`inputmode`。計算結果應在輸入區後方以摘要卡呈現，而不是迫使使用者橫向比對。

#### 60. 關鍵頁標題語意不完整

抽查 7 個關鍵頁，6 個沒有 H1；設定頁的 heading sequence 由 H2 開始。視覺上可能有頁名，但語意結構沒有同步。

影響包括：

- 螢幕閱讀器使用者無法快速確認目前頁面。
- heading 快速導覽失效。
- 元件區塊層級難以理解。
- 頁面標題與瀏覽器 title／導覽名稱容易逐漸不一致。

每頁應只有一個描述主要任務的 H1，例如「倉位計算器」「投資組合」「Agent 分析」；卡片區塊由 H2 開始，內層再用 H3。

#### 61. 首頁手機版仍保留 53 個操作元件，沒有依任務重新排序

首頁在 375px 寬度仍一次呈現搜尋、載入、自選、圖示、分析折疊、投資組合 tabs、市場篩選、來源 tabs 與多組策略控制。這是「縮小桌面 UI」，不是手機資訊架構。

對使用者而言，第一屏沒有清楚回答「現在最重要的事情是什麼」。建議手機首頁只保留：

1. 今日資料狀態。
2. 搜尋股票。
3. 一個主要決策摘要。
4. 持倉風險／待處理事項。
5. 其他研究工具入口。

進階篩選與來源切換放在 bottom sheet 或獨立頁，不要讓所有控制同時競爭注意力。

#### 62. icon-only 小按鈕缺少足夠辨識與操作空間

系統健康度的複製按鈕只有約 19 × 13px；header 也大量使用約 32px 的圖示按鈕。即使有 tooltip，手機沒有 hover；只看圖示未必能辨識是複製、重新整理、主題或設定。

建議：

- 提供 `aria-label` 與可見或長按可見的文字提示。
- 熱區至少 44px。
- 複製成功後顯示「已複製」狀態，不只改圖示。
- 高頻主要行動使用「圖示 + 文字」，不要只用 icon。

#### 63. 設定頁雖沒有溢出，但表單可及性仍不足

設定頁是本輪少數能在 375px 正常收進 viewport 的頁面，但 email 欄位依賴 placeholder，沒有可辨識 label；range slider 也沒有 label／aria 名稱。info 按鈕約 16px，slider 軌道約 6px 高，其餘操作多為 38px 以下。

這說明「畫面塞得下」不等於「手機可用」。設定頁應補上常駐標籤、目前值、最小／最大值、鍵盤操作與放大的觸控熱區。

#### 64. 同類篩選控制靠得太近，增加誤觸與語意混淆

市場、資料來源、報酬 horizon、最小樣本等控制都採用相似的小型 pill／tab，間距有限。手機上不只難點，也不容易看出哪些是單選、哪些是多選，以及每組控制的範圍。

建議每組控制都加可見 group label，組與組之間至少 16px，單一選項間至少 8px；單選使用 segmented control 或 radio semantics，多選使用 checkbox semantics。不要只靠外觀表示狀態。

### 手機版改善優先順序

1. **P0：消除整頁水平溢出**——先修倉位計算器、Agents、回測、投資組合。
2. **P0：重做手機 header**——確保頁名、返回／導覽與主要動作永遠在 viewport 內。
3. **P0：表單補齊 label 與單欄佈局**——優先倉位計算器與設定。
4. **P1：全站互動熱區至少 44 × 44px**——尤其複製、篩選、tabs、icon buttons。
5. **P1：每頁補唯一 H1 與正確 heading hierarchy**。
6. **P1：首頁手機版按任務重新編排**——不是單純縮字與換行。
7. **P2：統一 filter group、狀態回饋與 icon-only 控制的文字提示**。

### 建議的手機驗收條件

- 320、375、390、414px 寬度皆無整頁水平捲動。
- 所有主要流程只用單手觸控即可完成，不依賴 hover。
- 所有互動熱區至少 44 × 44px，或有等效的 44px 點擊容器。
- 每頁一個 H1；所有輸入都有常駐 label 與可程式辨識名稱。
- 鍵盤操作時 focus 清楚可見，順序與視覺閱讀順序一致。
- 200% 字體縮放後不截字、不重疊、不遺失功能。
- 重要狀態不只靠紅／綠區分，需同時有文字、符號或形狀。
- 錯誤訊息緊鄰欄位，說明問題與修正方法。

## 第五輪：端到端任務流程、錯誤回復與導覽狀態

測試目標：模擬第一次使用者從「找股票」開始，嘗試載入分析、加入持倉、前往試算與回測，再檢查返回、空狀態及錯誤時是否知道下一步。

### 已確認缺陷

#### 65. 股票搜尋的空白提交是 silent no-op

首頁搜尋框留空直接按「載入」後：

- 沒有欄位錯誤。
- 沒有 toast／alert。
- 沒有把 focus 移回搜尋框。
- 沒有說明可輸入的格式或範例。

按鈕只是取得 focus，使用者不知道點擊有沒有被系統接收。建議在欄位下方顯示「請輸入股票代號或名稱，例如 2330」，使用 `role="alert"`／`aria-live` 宣告，並將 focus 留在錯誤欄位。

#### 66. 輸入有效代號後，頁面同時呈現互相矛盾的三種狀態

輸入 `2330` 並按「載入」，等待後仍觀察到：

- 頂部顯示「載入K線圖中...」。
- 分析區顯示「尚未載入股票」。
- 「加自選」仍 disabled。
- URL 保持 `/`，沒有股票 identity。
- 沒有成功、錯誤、逾時或重試訊息。

這會讓使用者無法判斷系統究竟是 loading、empty、error 還是操作沒有生效。四種狀態必須互斥：

1. Initial：尚未選股。
2. Loading：顯示標的名稱、進度與取消／逾時策略。
3. Success：K 線與分析完成，解鎖後續動作。
4. Error：具體原因、重試與替代入口。

不能讓 loading 與 empty 文案同時存在。

#### 67. 空持倉的主要 CTA 點擊後沒有任何可見結果

投資組合空狀態同時提供頂部「+ 新增」、內容區「+ 新增第一筆持倉」及「去掃描選股」。實測點擊「+ 新增第一筆持倉」後：URL 不變、沒有 dialog、沒有輸入欄位、沒有 alert。

除了功能失效，三個 CTA 也沒有清楚的主次關係。建議空持倉只保留一個主要決策：

- 已知道股票：新增第一筆持倉。
- 還沒選股：次要文字連結「先去找股票」。

新增流程應開啟可被辨識的 dialog 或進入獨立 route，並在成功後把新增項目高亮、提供 undo。

#### 68. 7 個關鍵頁共用同一個瀏覽器標題

首頁、投資組合、倉位計算器、Agents、回測排行榜、設定、系統健康度的 `document.title` 全部都是：

`K線走圖練習器 — 台股陸股掃描選股與策略回測`

使用者開多個分頁、查看瀏覽紀錄或用螢幕閱讀器切頁時無法分辨。建議格式：

- `投資組合｜Rockstock`
- `倉位計算器｜Rockstock`
- `2330 台積電分析｜Rockstock`

頁面 H1、document title、全域導覽名稱應來自同一份 route metadata。

#### 69. 所有抽查頁都缺少目前位置狀態

7 個關鍵頁沒有任何 `aria-current`。Header 裡的持倉／健康入口不會告訴使用者目前位於哪一頁，視覺 active state 也缺少穩定語意。

建議目前頁面的導覽項目加上 `aria-current="page"`，tabs 使用 `aria-selected`；頁面名稱同時在 header 或 H1 顯示，不能只依靠返回箭頭推測位置。

#### 70. 全站重複出現兩個功能相同的 skip link

每個抽查頁都有：

- 「跳至主要內容」→ `#main-content`
- 「跳到主要內容」→ `#main-content`

鍵盤使用者第一次 Tab 就遇到重複選項。這通常表示兩層 layout 各自注入一次。全站只保留一個 skip link，focus 後可見，啟動後 focus 應真正落到 `<main id="main-content" tabindex="-1">`。

#### 71. 多個 header 導覽連結沒有可見文字也沒有 accessible name

跨頁檢查發現 `/portfolio`、`/health` 等 header link 的 text 為空，`aria-label` 也為 null。視覺上依賴圖示，但輔助科技只會遇到沒有名稱的 link。

建議：

- 每個 icon-only link 必須有描述目的地的 `aria-label`。
- 常用目的地在桌面版顯示文字；手機版即使收進 menu，也保留可見名稱。
- 裝飾 icon 使用 `aria-hidden="true"`，避免圖示名稱干擾 link 名稱。

#### 72. 核心工具之間沒有「下一步」，只能回首頁

抽查到的內部連結圖：

| 目前頁 | 可到達的主要任務 |
|---|---|
| 首頁 | 投資組合、系統健康度 |
| 投資組合 | 首頁／掃描、系統健康度 |
| 倉位計算器 | 首頁、投資組合、系統健康度 |
| Agents | 首頁、投資組合、系統健康度 |
| 回測排行榜 | 首頁、投資組合、系統健康度 |
| 系統健康度 | 投資組合、系統健康度 |

使用者在候選、Agent 結論、倉位試算與持倉間不能自然前進。各頁像獨立 demo，沒有形成完整工作流。

建議以股票作為跨頁 context，建立固定下一步：

`候選股票 → 查看證據 → 反方／風險 → 倉位試算 → 加入觀察或持倉 → 設停損 → 事後回顧`

每一步都應保留 symbol、市場、資料日期與使用者已輸入值。

#### 73. 股票、tab、filter 狀態沒有可分享的 URL

首頁分析分頁、資料來源、台股／陸股、多／空、策略等都使用 button；載入 `2330` 後 URL 仍為 `/`。因此使用者不能：

- 書籤特定股票或分析頁。
- 分享同一組篩選結果。
- 重新整理後回到原狀態。
- 使用瀏覽器返回逐步撤銷篩選。

建議至少支援 `/stocks/2330?panel=fundamental&market=tw`；高頻 filter 寫入 query string，純視覺折疊狀態可以留在 local state。

#### 74. Loading 沒有逾時、取消或 recovery path

「載入K線圖中...」沒有進度、耗時預期、重試、檢查資料健康度或返回搜尋的動作。長時間停留時，使用者唯一選擇是盲等或重新整理。

建議：

- 0–3 秒：skeleton 並保留版面高度。
- 3–10 秒：顯示「仍在載入 2330 台積電資料」。
- 超過門檻：顯示可能原因與「重試」「查看系統狀態」「換一檔股票」。
- 若部分來源成功，呈現 partial success，不要讓整頁永久 loading。

#### 75. 核心操作缺少 pending／success／failure 回饋契約

股票載入與新增持倉都出現「點擊後 UI 無可見變化」。即使根因是目前 local build 的互動程式未正常執行，從 UX 驗收角度仍屬 P0：使用者沒有任何可觀察的操作結果。

所有 mutation／async action 應共用狀態契約：

- Pending：按鈕 disabled、文字改為動詞進行式、避免重複提交。
- Success：就近更新內容並提供簡短確認。
- Failure：顯示原因、保留使用者輸入、提供重試。
- Timeout：明確結束 loading，不允許無限等待。

### 建議的端到端主流程

1. 首頁顯示資料截至時間與全站健康摘要。
2. 搜尋並選定股票後，URL 取得 symbol。
3. 個股頁先給一句決策摘要，再展開證據、反方與資料完整度。
4. 「試算倉位」帶入 symbol 與目前價格。
5. 完成試算後提供「加入自選」與「新增持倉」兩個明確分支。
6. 新增持倉時帶入試算結果，讓使用者確認成交價、股數、停損與理由。
7. 持倉頁顯示下一個待辦與失效條件。
8. 平倉後自動進入回顧，不把事後結果混回原始決策。

### 第五輪優先處理清單

1. **P0：修復股票載入與新增持倉點擊無結果。**
2. **P0：建立互斥的 initial／loading／success／error 狀態。**
3. **P0：所有錯誤提供就近訊息、重試與輸入保留。**
4. **P1：以 symbol 串起個股、試算、持倉與回顧。**
5. **P1：股票與主要 filters 寫入 URL，支援分享與返回。**
6. **P1：每頁提供唯一 title、H1 與 `aria-current`。**
7. **P1：修正無名稱 icon links 與重複 skip link。**
8. **P2：統一空狀態 CTA 層級與成功後 undo。**

## 第六輪：視覺層級、金融數字與資料可讀性

測試條件：Chrome 桌面 viewport 實測 computed styles，抽查首頁、投資組合、倉位計算器、Agents、回測排行榜、設定與系統健康度。此輪不只看「好不好看」，而是看使用者能否快速找到結論、比較數字並辨識風險。

### 字級量化摘要

| 頁面 | 抽查可見文字節點 | 小於 12px | 12px | 16px 以上 |
|---|---:|---:|---:|---:|
| 首頁 | 75 | 46 | 26 | 1 |
| 投資組合 | 17 | 2 | 6 | 3 |
| 倉位計算器 | 18 | 0 | 10 | 2 |
| Agents | 31 | 27 | 1 | 2 |
| 回測排行榜 | 37 | 4 | 20 | 4 |
| 設定 | 38 | 3 | 16 | 0 |
| 系統健康度 | 13 | 2 | 4 | 3 |

首頁出現 9、10、11、12、14、24px 六種字級；Agents 出現 9、10、12、14、18px，其中排序控制大多為 9px。這些是瀏覽器實際計算尺寸。

### 已確認缺陷

#### 76. 首頁與 Agents 的文字尺寸已低於一般可讀介面範圍

首頁 75 個抽查文字節點中有 46 個小於 12px；Agents 31 個中有 27 個小於 12px。實例包括：

- 首頁「全部／台股／陸股」：10px。
- 首頁「副圖」：9px。
- 首頁持倉／自選 tabs：11px。
- Agents「排序」與排序選項：9px。
- Agents 欄位名稱：10px。
- 系統健康度複製圖示：10px。

使用者必須靠近螢幕或放大才能閱讀；資料密度反而降低掃讀效率。建議正文與主要控制以 14px 為桌面下限，輔助 metadata 最低 12px；9–10px 不應承載可操作控制或決策欄位。

#### 77. 字級縮小取代了真正的資訊層級

目前的做法是「資訊越多就越小」，但小字同時包含：篩選、排序、欄位名稱、策略名稱、狀態與風險。使用者無法只靠視覺回答：

- 哪個是頁面結論？
- 哪個是可操作控制？
- 哪個是證據？
- 哪個只是 metadata？

建議建立固定 type scale：

- Page title：24px／700。
- Section title：18px／600。
- Card title／重要數字：16px／600–700。
- 正文與控制：14px。
- Metadata／註記：12px。

層級應主要由分組、留白、字重與位置建立，而不是持續縮小字體。

#### 78. 大量 muted text 同時使用小字與透明度，存在明顯對比風險

實測多個 10–12px 說明文字使用約 60% alpha 的 muted foreground。例如首頁空狀態提示、投資組合免責聲明、設定說明與回測警語。即使單獨色值勉強通過，透明度疊在不同 card 背景後仍可能降低對比。

本輪沒有逐色完成 WCAG contrast ratio 計算，因此此項列為**高可信度呈現風險**，不是已宣告的 WCAG 數值違規。建議以實際 light／dark 背景逐組測量：正文至少 4.5:1；12px 風險與說明文字也不能使用弱對比處理。

#### 79. 比較型頁面完全沒有資料表語意

Agents 與回測排行榜視覺上呈現欄位、排序與列資料，但 DOM 中：

- `table`：0。
- `role="table"／"grid"`：0。
- `row`：0。
- `cell／columnheader`：0。

螢幕閱讀器無法知道數字屬於哪一欄；鍵盤使用者也沒有表格導覽能力。建議靜態比較資料使用原生 `<table>`；需要互動選取才考慮 grid。表頭要有 `scope`，排序按鈕使用 `aria-sort`，並提供 caption 描述資料期間與單位。

#### 80. 金融數字未採 tabular numerals，長度變動時難以垂直比較

回測頁數字的 `font-variant-numeric` 實測為 `normal`，而且重要績效多嵌在長句中、靠左排列，例如 `−8.82%`、`0%`、`n=31` 與 `+4.8pp`。

建議表格與 KPI 數字使用 `font-variant-numeric: tabular-nums`，數值欄右對齊；百分比、小數位、樣本數、區間使用一致格式。敘述可以留在「解讀」欄，不要與主要比較數值混成一整句。

#### 81. 回測重要發現以 917px 長句呈現，掃讀成本過高

回測頁的核心結論與警語以 12px、約 917px 寬的單行／長段文字呈現。例子同時包含策略 id、d5、報酬、勝率、樣本量與解讀。這遠超過適合連續閱讀的 65–75 字元行長，也讓最重要的負面訊號看起來像註腳。

建議改成結構化 insight card：

- 標題：法人看多可能是落後指標。
- 主數字：d5 −8.82%。
- 輔助數字：勝率 0% · n=31。
- 信心：中／小樣本。
- 解讀：報告常出現在行情末段。

使用者先讀懂結論，再決定是否展開方法細節。

#### 82. 重要警語與一般說明採用相近的視覺重量

回測頁「真正該避的是什麼」、投資組合的資料保存／非投資建議、設定頁不可恢復操作等，許多都落在 10–12px muted text。重要性完全依賴使用者逐字閱讀，而不是視覺層級。

建議警示分級：

- Critical：會造成資料刪除、金錢風險或不可恢復，使用明確 alert 樣式與確認。
- Warning：資料不足、模型限制，以 icon + 標題 + 一句影響呈現。
- Note：一般方法說明，可放 12px muted text。

不要把所有風險都做成頁尾小字。

#### 83. Emoji 被當成主要 UI icon，圖示語言不一致

實測主要控制包含 `📺`、`🔥`、`🏦`、`📈`、`⭐`、`⬅️`、`📐`、`📋`、`ⓘ` 等 emoji；其他位置又使用 SVG。Emoji 會因作業系統而有不同外觀、基線與彩色風格，難以與金融產品的嚴謹視覺一致，也可能產生重複的輔助名稱。

建議採用同一套 SVG icon（例如 Lucide），固定 16／20／24px 三種尺寸。圖示只是輔助；主要導覽仍應有文字。策略本身的 emoji 若是使用者記憶符號，可保留為 badge，但不要兼任按鈕功能說明。

#### 84. 使用者介面暴露工程與內部規則用語

實測看到：

- 設定頁：「CLAUDE.md Rule 5」。
- 系統健康度：`npx tsx scripts/audit-l1-integrity.ts TW 7`、`insert-missing-day.ts`。
- 回測頁：「2 年回測 harness」「執行 scripts/backtest-unified-leaderboard.ts」。
- 回測洞察：`broker_bullish`、`youtube 原始 bullish`、`alpha`。
- 倉位計算器：「走 sizing-config 預設」。

一般使用者不該需要理解 repository、CLI、英文 enum 或 agent 開發規則。這些字詞也會讓產品看起來仍是內部工具。

建議建立兩層呈現：

- 使用者層：白話狀態、影響與可執行動作。
- 維運層：命令、檔案、策略 id，放在「技術詳情」或管理員模式。

例如「缺少部分台股資料」作為主訊息；具權限的維運者展開後才看到修復命令。

#### 85. 對空資料使用巨型 emoji，卻沒有同等強度的下一步

回測空狀態實測 `📊` 為 48px，而真正的說明與執行方法只有 12px。視覺焦點落在裝飾 emoji，不是「為什麼沒有資料」與「現在能做什麼」。首頁也有類似做法。

空狀態應把注意力交給：狀態標題、原因、主要 CTA、次要說明。插圖／icon 可以存在，但不應成為整張卡最強且唯一的大元素。

### 建議的金融資料卡視覺規格

1. 第一行：股票名稱、代號、市場、資料時間。
2. 第二行：一句結論與狀態 badge。
3. 主數字區：報酬／風險／信心，採 tabular numerals 並標示單位。
4. 證據區：最多三項，數值與敘述分欄。
5. 反方區：最大風險與失效條件，不使用弱對比小字。
6. Footer：樣本數、期間、資料來源與方法詳情入口。

### 第六輪優先處理清單

1. **P0：首頁與 Agents 移除 9–10px 操作文字。**
2. **P1：建立全站 12／14／16／18／24px type scale。**
3. **P1：Agents／回測改用具語意的資料表或等效 table semantics。**
4. **P1：金融數字使用 tabular numerals、右對齊與一致格式。**
5. **P1：回測洞察改成結論／主數字／樣本／解讀四層卡片。**
6. **P1：重要警語從 muted 小字提升為分級 alert。**
7. **P2：統一 SVG icon，移除功能性 emoji。**
8. **P2：工程命令與內部規則收進管理員／技術詳情。**

## 第七輪：鍵盤操作、Focus 與動態效果

測試方式：從重新載入的首頁只使用 Tab、Enter 與方向鍵操作，記錄前 15 個 focus 停駐點、computed focus styles、tabs 語意、separator 語意與 active element。另檢查實際動畫及 `prefers-reduced-motion` CSS 覆蓋。

### 已確認缺陷

#### 86. 搜尋框取得鍵盤 focus 時沒有可見 outline

首頁第三個 Tab 停駐點為股票搜尋框；實測 focused input 的 computed `outline-style` 為 `none`、`box-shadow` 為 `none`。使用者只能依賴游標或猜測目前位置。

主題切換按鈕同樣沒有有效 outline，box-shadow 也完全透明；其他多數元件只使用瀏覽器 1px auto outline，跨深色背景未必足夠醒目。

建議所有互動元件統一使用 `:focus-visible`：至少 2–3px、與背景對比清楚、保留 2px offset。不要用 `outline: none`，除非有可見且等效的替代樣式。

#### 87. Tab 順序與畫面閱讀順序明顯不一致

首頁前 15 個 Tab 停駐點的實測座標顯示：

- Header 控制後，focus 先跳到頁面下方 `y=524` 的「副圖」控制。
- 下一步又跳回 `y=58` 的分析 tabs。
- 接著跳到 `y=268`、`y=296` 的持倉區。

鍵盤 focus 在畫面上上下來回跳，使用者很難追蹤。這通常代表 DOM order 與 CSS grid／絕對定位的視覺 order 不一致。

建議 DOM 本身就依照：header → 主要圖表 → 分析區 → 持倉 → 右側研究工具排列；不要使用正數 `tabindex` 補洞。Responsive 重新排列後也必須保持語意與視覺順序一致。

#### 88. Skip link 改變 hash，但沒有把 focus 移到 main

實測在第一個「跳至主要內容」按 Enter 後：

- URL hash 變成 `#main-content`。
- 畫面只捲動約 7px。
- `document.activeElement` 變成 `BODY`，不是 `MAIN`。

因此鍵盤使用者下一次 Tab 不一定從主要內容開始，skip link 的核心目的沒有完成。建議 `<main id="main-content" tabindex="-1">`，啟動 anchor 後確保 focus 落在 main；並移除重複的第二個 skip link。

#### 89. Tabs 沒有實作 roving tabindex，方向鍵也無效

首頁兩組 tablist 共 9 個 tabs。實測每個 tab 都沒有明確 `tabindex`，所以全部進入正常 Tab 順序。對「條件」按 ArrowRight 後：

- focus 仍留在「條件」。
- selected 仍是「條件」。
- 沒有移到「訊號」。

正確 tabs pattern 應只讓目前 selected tab 使用 `tabindex="0"`，其餘為 `-1`；Left／Right 切換 focus，Enter／Space 或自動模式切換 panel。這能把 9 次 Tab 降成 2 次 tablist 停駐。

#### 90. 可拖曳的圖表分隔線完全無法用鍵盤調整

「拖拽調整 K 線圖與副圖比例」具有 `role="separator"`，但實測：

- 沒有 `tabindex`。
- 沒有 `aria-valuenow`。
- 沒有 `aria-valuemin`／`aria-valuemax`。
- 無法取得鍵盤 focus。

滑鼠可拖曳但鍵盤不可操作。建議 separator 可聚焦，Arrow keys 小幅調整，Shift + Arrow 大幅調整，Home／End 到上下限；同步宣告目前比例及範圍。另提供「重設比例」按鈕。

#### 91. 鍵盤會停在沒有名稱的 header links

首頁第 5、6 個 Tab 停駐點為 `/portfolio` 與 `/health`，兩者實測 active text 為空。這與前輪發現的 accessible name 缺失一致，但鍵盤實測顯示影響更直接：focus ring 套在 32 × 32px 圖示上，使用者無法從文字或輔助名稱判斷按下 Enter 會去哪裡。

應補上 `aria-label="投資組合"`／`aria-label="系統健康度"`，並讓 tooltip 在 keyboard focus 時也可見，不只 hover。

#### 92. 首頁一次提供 55 個可聚焦元件，缺乏分區跳轉

實測首頁共有 55 個可見 focusable elements。即使每個元件都能操作，鍵盤使用者仍要經過大量策略、篩選與 tabs 才能到達後段內容。

建議：

- 修正 tabs roving tabindex。
- 收合進階策略時，內部控制不可仍被 focus。
- 提供「跳到分析」「跳到持倉」「跳到策略」等區域導覽，或清楚 landmark + heading。
- 低頻策略放進可搜尋的單一選擇器，而不是數十顆按鈕。

#### 93. Reduce-motion 只覆蓋局部元件，沒有涵蓋首頁 loading 動畫

首頁實測存在：

- `fadeIn`：0.4 秒。
- loading `pulse`：2 秒。

CSS 中雖有 `prefers-reduced-motion`，但只找到對 `.shimmer` 與 toast 的處理，沒有涵蓋這兩個 `fadeIn`／`pulse` 動畫。因此「減少動態」偏好可能仍看到持續 pulse。

建議在全域 reduced-motion media query 中停用非必要 animation／transition；loading 狀態改用靜態 spinner icon + 文字，或將 pulse 降為無位移、低頻率且可停的狀態。

#### 94. 200% zoom 本輪未取得可靠瀏覽器量測

本輪嘗試以瀏覽器快捷鍵切換 zoom，但 viewport metrics 沒有可驗證的變化，因此沒有把 200% reflow 宣告為通過或失敗。此項屬**資料限制**，不是產品缺陷結論。

仍建議正式驗收依 WCAG reflow 情境測試：在 1280px CSS viewport 放大至 400%（等效約 320px 寬）時，除二維資料表／K 線圖外，不應要求雙向捲動；200% 下文字不截斷、控制不重疊、dialog 不超出 viewport。

### 建議的鍵盤驗收腳本

1. 第一次 Tab 只出現一個 skip link。
2. Enter 後 focus 落在 main，下一次 Tab 是主要任務的第一個控制。
3. 搜尋框、icon button、一般 button、link、tab、slider 都有一致可見 focus ring。
4. 每組 tablist 只佔一個 Tab 停駐點，方向鍵可切換。
5. 圖表 resize separator 可用方向鍵操作並宣告目前值。
6. 收合區內容不進入 Tab order；展開後才可操作。
7. 全頁沒有 focus trap，Shift + Tab 可逆向返回。
8. reduced-motion 下不持續 pulse、bounce 或大幅位移。
